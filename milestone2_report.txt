LinkedQueue Complexity
Adding a new node takes constant, O(1), time in the LinkedQueue because insertion happens right at the end. 
Instead of traversing through nodes, the tail reference simply shifts forward. This update avoids full traversal. 
Removing an item takes constant, O(1),  time because the first node gets deleted while the head reference updates directly. 
No iteration is required for either operation.  

Sorting Algorithms Complexity

Insertion Sort:
In the worst-case, time complexity goes up to O(n²) when the list is in reverse order, since every item must shift after comparisons.
Best-case time complexity is O(n) when the list is already sorted, and no rearranging is needed. 
The average case is O(n²).
However the algorithm is adaptive meaning its performance improves when the list is partially sorted, because it performs less shifts. 

Selection Sort:
The time complexity is always O(n²) because it keeps scanning the unsorted portion of the list to find the minimum element.

Recursive Binary Search Complexity
Recursive binary search is O(log n) time since the searching area is cut in half at each recursive step. 
Because comparisons rely on an order, sorted data is necessary for the search to work appropriately. 
Without sorting, the algorithm cannot figure out whether to search the left or the right half after comparing the middle element.

Comparison of Sorting Algorithms
Insertion sort is generally better for small or nearly sorted datasets since it can run in linear time in the best case and also it performs fewer operations when data is already partially ordered.
Selection sort might be preferred when swapping is costly, as it performs only one swap at most per iteration, although it still has O(n²) comparisons.
